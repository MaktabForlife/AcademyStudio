# New Course registration — local candidate

`POST /internal/studio/course-publication` is a purpose-bound signed Academy server route, available only in ACADEMY integration mode. A browser cannot supply an Admin actor or native proof here. The source issues the capability only from a durable first-publication job accepted in its existing current scoped/session/epoch/revision guarded publication transaction. Registration binds the stable Course, activity, run, publication, access model and registration IDs. Conflicting registrations are rejected. No native Global Admin/session is fabricated.

Registration creates operational Course metadata without creating a teaching website, publication, purchase or audience. Target0005 seeds nothing. Free Course material access uses its explicit model rather than a fake purchase. Paid Course purchases and acquired rights retain their normal semantics. An ordinary current Studio Admin remains required to attach/publish media; Academy still owns staff assignments. The legacy Academy media authority gap remains a separate follow-up.

The machine route shares the exact participant/revision/generation/version/cancellation/checkpoint algorithm with the native Global Admin handover. Its mutation guard is anchored to the immutable first-publication registration. The native route keeps its own real current Global Admin/session checks. Ordered source deltas import the existing rights before COMMITTED; Studio rights are not reconstructed from late source access proofs after transfer. Scope/master/staff/live rules and43200/43200/60 freshness are unchanged.

Recovery uses exact registration and operation receipts. Unknown outcomes leave source access FROZEN until a matching commit is confirmed. Changed checkpoints are permanently cancelled before another transfer starts; pending jobs never unlock source access as part of retry. Source cron processes one bounded job step, indexed source import/outbox work, and pages of at most25 people. There are no per-page/per-media Academy calls, account sweeps or browser polling.

Paired source: `Academy-course-studio-publication`, same feature branch. Source0016 and target0005, matching code and a coordinated activation of the absent-by-default source `ACADEMY_COURSE_STUDIO_PUBLICATION=1` are required. Legacy new-subject creation redirects to Course management while that flag is enabled, preserving the creation marker. Only Courses created while that policy is enabled are eligible; all historical/unmapped Course records and drafts stay unchanged. Normal copies/repeats get fresh identities, rosters without cloned purchases and independent setup on their own first publication. Later publication of the same Course refreshes published metadata without another registration/ownership transfer.

Run the full local suite with `ACADEMY_SOURCE=../Academy-course-studio-publication npm test`. The new `course-publication.test.mjs` uses disposable Workers/D1 and blocked external access; its `__local` fault routes are generated only in the test adapter and are absent from shipped code. No hosted checks, deployment, content/media writes, live authority operation, R2 copy, screen retirement, DNS update or Git push were performed for this candidate.

Existing scale boundary: Source sign-in preparation retains its32-enabled-scope ceiling. The4000-record job-cost fixture contains completed jobs, not4000 enabled scopes. A separate lazy/per-offering proof refresh is required before exceeding that existing ceiling; this feature does not remove it or claim its read measurement covers it.

Roster boundary: Course duplication defaults to no learners. Academy-owned rosters can be explicitly copied without purchases. A FROZEN/STUDIO-owned roster cannot be read back from old Academy records for duplication; structure-only copies remain available, with new enrolment managed in Studio after publication. A current Studio-roster export is separate work. This prevents a revoked old source enrolment from becoming a new live audience.
