### Preserve identities and counter domains

Studio's `accounts.account_id` carries Academy's existing account ID. Hifz resolves `academy_profile_links.academy_user_id` to the unique `student_id` that owns native records. Its login alias is not a replacement owner key. Preserve existing links and conflict handling; never assume a legacy student's ID equals the Academy ID merely because new profiles can use it. See [Hifz profile receiver](https://github.com/MaktabForlife/Hifz/blob/ba0ea53f23b933b0c175c87fe41788df74afbb2f/worker/src/academy-profile-sync.js#L43) and [link constraints](https://github.com/MaktabForlife/Hifz/blob/ba0ea53f23b933b0c175c87fe41788df74afbb2f/worker/migrations/0032_academy_profile_sync.sql#L2).

Do not substitute one kind of revision for another:

- Academy's `account_credentials.credential_epoch` identifies credential changes. Role, subscription and split-permission revisions have their own semantics.
- Studio's `accounts.epoch` projects Academy's credential epoch through its signed master account stream. `stream_heads.version` orders one stream; `source_access_scopes.generation` and `source_access_people.version` describe another boundary; `access_revisions.revision` is per offering.
- Hifz's `academy_profile_links.source_revision` orders profiles, `source_credential_epoch` tracks Academy input, and `students.credential_epoch` is a local cancellation value. The receiver increments the local epoch for a reset or changed compatible credential; it does not assign the source integer to it. These values can differ and must not be compared as interchangeable counters. See [ordered profile application](https://github.com/MaktabForlife/Hifz/blob/ba0ea53f23b933b0c175c87fe41788df74afbb2f/worker/src/academy-profile-sync.js#L51).
- Proposed JWT `pv`, `ce`, browser/unlock generations, refresh generations and parent tombstones are security state in the prototype. No existing revision becomes one of them merely by renaming it.

The child's admission adapter must prove the existing identity mapping and preserve the appropriate local security binding. No rekey, link repair, alias reassignment, epoch reset or metadata backfill is authorised here.
