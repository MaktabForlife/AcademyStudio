# Academy Admin access migration — local implementation

30 October 2026. Local feature only. Live remains Studio V108.5 / Academy source V108.4. Dashboard commits `8746806` / `804c4e1b` are separate local work, not a deployed V108.6. This feature does not authorise deployment, hosted schema/data changes, ownership activation, publication, DNS, retirement or push. All 49 enabled originals and their associations are retained.

## Ownership

Academy remains master for identity, PIN/security, admission/suspension, credential epoch, session revocation, scoped staff roles, class allocations and timetable/Zoom/lifecycle. Studio becomes the single editable authority for an explicitly handed-over offering's participation, whole-Course purchases, historical paid months/cohorts and Surah website grants. Staff-role transfer is deliberately excluded: native Academy Admin eligibility still depends on Academy staff roles. Studio denies staff-role edits in this integration and refreshes the current exact staff projection before sensitive administration. Removing/downgrading a source Admin also closes native Studio editor/admin routes on receipt, and stale sensitive proofs fail closed.

Ordinary account/live proofs retain the deployed 43,200-second policy; sensitive staff checks remain 60 seconds. No raw PIN is stored. Former participation never automatically revokes a purchase or paid month. Course cancellation/completion or archive closes live entry without expiring acquired materials. Reviewed migration-scope availability is separate from live lifecycle; suspended accounts can be reconciled with their retained purchases intact, while master entry stays blocked. An explicit received master-state mismatch fences Studio immediately until ordered master state is confirmed; an unrelated oversized live/class proof does not remove acquired materials. Surah-only grants never unlock recordings; original lesson month and cohort still govern Tafseer recordings. Academy website mapping, withdrawal, class/date, audience and Join window checks remain after handover.

## Academy screen and contract

The existing Programme/Course Participants flow mounts `m4l-studio-access.js`. A migrated offering bypasses the old full participant reader, uses keyset pages of 25, and opens one exact account's rights. Non-migrated programmes retain their existing controls. No new Global Admin workspace item is added. Existing User-profile writes to handed-over Student/access records fail clearly; master and staff changes remain available.

Browser: `POST /api/admin/platform/studio-access` with `{activityKey,command}` under the actual Academy bearer session, Admin workspace and exact configured Academy Origin. Actor/role/offering hints never confer authority. Academy resolves the explicit offering mapping, verifies current Core session/admission/epoch, and forwards a signed bounded request to `POST /internal/studio/access`. The 55-second server-only proof uses a source session reference; no browser receives it, a Studio token or a server secret. Target independently checks the local master/session, current exact role, source staff proof, ownership and atomic mutation guard. Received revocations have persistent tombstones, including before any local session exists.

Commands: `read {after?,accountId?,known?}`, `save {revision,change}`, `provision {input}`, `resume {input}`. Save accepts only participation, paid months and Surah grants in this phase. `access-batch` holds up to 40 bounded edits, 240 month cells per month change, one operation receipt and one transaction. Participant rows and month cells use bulk JSON statements; no network write per checkbox. Removals require reasons and preserve an audit. Revision conflicts never partially save. Exact retries recover a lost acknowledgement; changed retries conflict. Empty reads reuse the same revision cache after rechecking authority. Cache data is memory-only and account-bound; pending enrolments can be resumed from the server list.

Identity is created/explicitly linked in Academy first, then enrolled in Studio without a purchase. A failed enrolment keeps the successful identity and its receipt. Retrying an existing identity receipt after a new authenticated Admin epoch still resolves that identity under current scope; it cannot create a second account. New identity creation requires the prepared epoch. Scoped Course Admin can create, while only Global Admin can link an existing master identity. Class allocation remains in Academy. The same Admin screen includes a narrow Tafseer class/date editor: the source first confirms current Studio enrolment through the signed target read, then atomically checks current source Admin/session, exact class/row, ownership and an idempotent source receipt. It grants no duplicate Student role or material rights. Concurrent row changes conflict; current class facts reach Studio through the existing bounded delivery. A new Studio-only learner therefore does not need a second source participation authority.

## Guarded offering handover and recovery

Schemas `0004_studio_access.sql` (target) and `0015_studio_access_admin.sql` (source) are additive and seed no transfer. Applying them never activates Studio ownership. Run the protocol only after separate live approval, a reviewed source/target pairing, a private source backup and exact offering mapping review.

1. Global Admin starts a transfer with a new stable `transferId`. Academy atomically freezes that offering's access and staff writes. Master account/session and timetable streams continue. No automatic timeout unlock exists.
2. Reconcile the final source import in bounded pages and deliver/acknowledge every current scoped access delta. Existing dirty accounts include former holders whose rights were removed. Imports, errors, generations and pending deliveries must be clear before proceeding.
3. Begin the target checkpoint against its exact current source scope version and access revision. Source supplies ordered participant pages of at most 25. Each page must exactly match the target's complete retained member index and delivered per-person stream versions; missing/extra participants fail. Any concurrent access/fact change invalidates the checkpoint. Resume exact steps or abort and start another transfer.
4. After the final page, Academy itself confirms no further source accounts or undelivered/current changes. A Global Admin target transaction checks the checkpoint, complete participant coverage, current role/session and unchanged revision, records COMMITTED and switches that offering. A raw authority-column flip is rejected by a trigger. Academy records STUDIO only after target acknowledgement. If that acknowledgement is lost, keep source FROZEN and retry the same commit; do not unlock it.
5. Before target commit, `handover-abort` confirms target state and aborts its checkpoint before unfreezing Academy. After target commit, reverse migration requires a separate reviewed reconciliation; automatic rollback is refused. If the acting Admin loses scope, a current Global Admin must recover; gates are never weakened to unblock the operator.

Source staff roles reopen after STUDIO ownership, while Student/access controls and the retired billing-policy controls stay fenced. Late/in-flight participant/month/grant deltas are consumed in ordered streams without changing Studio rights. Current source staff/class/live metadata continues; obsolete source generations are acknowledged without restoring access. Account/credential/session deliveries remain independent and cannot be permanently poisoned by a handed-over access event. After handover, source projections stop querying old purchase/month/grant records for ordinary actor refreshes.

## Verification and review

A validation error acknowledges already accepted source proofs, so correcting the field does not manufacture a revision conflict. No real account, hosted SQL/R2 operation or content publication is part of this work.

Native read evidence is written to ignored `outputs/studio-access-reads.json`. Baseline Admin exact-account view: 111 Academy rows and 61 target rows. After 4,000 unrelated rights/accounts/history: 222 Academy rows on the first source proof refresh and 120 target rows for the bounded page. Successful empty-rights cache reuse: 31 target rows, down from 121. One 20-person Save: 111 Academy rows and 200 target rows, 39 target queries including current authority, transaction triggers, audit and receipt. Ordinary protected website reading: zero Academy queries. These are measured synthetic workflow costs, not a prediction of aggregate production traffic.
