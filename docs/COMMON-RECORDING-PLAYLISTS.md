# Common recording playlists

Native Studio Tafseer, MOU and Courses share explicit playlists independent of timetable sessions. Existing `mou-playlists` transport aliases and schema label remain compatible. The checked native offering determines `accessModel: MONTHLY|COURSE`; browser claims cannot change it.

New playlists create private, empty native website wrappers. Admin saves names and an optional close date; new Tafseer Surahs may remain OPEN. Monthly OPEN playlists use the current server month in the signed native programme timezone; CLOSED playlists use the close-date month. Closing does not retain every earlier open-month payment. A later correction to a saved closed month requires reviewed holder preservation, bounded to250 accounts/1000 paid-cohort rows. Removing the last original paid cohort deletes retained recording access; later regrant does not resurrect it. Website months and individual Surah grants give text access only.

Courses keep their existing whole-course FREE/PAID policy and perpetual purchases/PDF rights; close dates are editorial. No new per-person free enrolment or invented date/session is created. Existing live/current class/date/Join and completed-Course gates are unchanged.

Legacy websites are displayed with `legacy:true,readOnly:true,state:LEGACY` and their original qualifying month. They are never adopted or converted by reading the catalogue. Explicitly adding an existing recording creates a reference without changing its native parent, source, publication state or old endpoint rights. Native new Tafseer/Course media uses the selected wrapper; reviewed MOU cross-parent support remains compatible. New private playlist media and supporting PDFs/companions require a published recording, a separately published playlist and current material entitlement. Raw attachment/publication paths cannot bypass the checked playlist form.

Admin table: GET `/api/admin/:offering/playlists`; optional `attachment` shows membership, optional `playlist` returns up to400 ordered `items`. The signed Source proxy uses the same existing MOU command names. `mou-playlist-order` takes `operationId,playlistId,revision,playlistRevision,entries:[{attachmentId,position}]`; every current member must appear exactly once with positions1..count. New members append; the unchanged native attachmentId retains its position when source/title metadata changes. Initial0012 memberships retain their former attachment-ID order. No inferred session/title/date linkage exists.

Protected learners: GET `/api/offerings/:offering/playlists` returns published entitled descriptors; existing website and checked access catalogues discover new monthly wrappers. Selected media feeds retain `after=attachmentId`, resolve it to explicit saved position, return `playlistPosition` and `playlist:{id,name,revision}`; optional `playlistRevision` rejects changed pagination. Published checked attribution supplies row `playlistId` and `playlist:{id,name}`. No automatic public R2 catalogue/card publication is performed; the separate UI owner must consume the protected descriptors.

Ordinary views keep twelve-hour proof reuse. Save, correction, Attach, Publish and order writes retain sixty-second current Admin verification, Source session/epoch/master/role/ownership and atomic revision/receipt guards. No per-card/per-file Source call, polling or global account/media sweep is introduced. Lists cap100 registered/200 legacy rows; catalogue requests50 IDs; account scope discovery32 monthly offerings; ordered edits400 recordings.

Schema0013 is additive over deployed0012 and was reserved by the paired release owner. It generalises retained-right deletion triggers and adds a separate indexed positions table; existing membership insert layout and native rights/media are preserved. Apply schema before the paired runtime/UI composition. Once new Course/Tafseer playlist data exists, recovery must retain this generic playlist publication/entitlement runtime and compatible assets/Source proxy: unmodified older Studio code can ignore the new Course wrapper publication gate. Do not remove schema, rights or media as rollback. Root alone performs the approved paired release; this feature performed no live request, hosted SQL, media attachment/publication, deployment, DNS action or push.
