# Protected dashboard week cache

POST `/api/circles/dashboard` accepts existing `mode,refresh` plus optional `date` OR `weekStart`, never both. A real civil date selects the containing Sunday–Saturday week. Default uses the trusted native timezone/current day. Responses retain `startDate,endDate,timezone` and add `timetableWeekVersion:1,weekStart,weekEnd,selectedDate,today,serverTime,weekToken,dateBrowsingAvailable`. Day changes inside the returned seven dates need no request; explicit cross-week navigation fetches one bounded native week. Join is still evaluated under the actual clock and current permission, never the selected date.

A new Source uses its existing checked entrance with `startDate`; no new Source Worker route exists. Teach may receive the native safe opaque `meeting-N` grouping label, never a meeting URL. The existing native programme/class/Teacher/date and publication/lifecycle filters and exact native/Studio Join references are preserved. A transitional older Source can serve only its validated current seven dates, uncached; mismatched requested weeks fail closed and `dateBrowsingAvailable` is false. It never invents a week.

Private R2 keys include account hash, source reference/epoch/navigation-proof context, authoritative native account-stream revision, mode and normalised week. The account revision invalidates even when programme membership, epoch and millisecond timestamp are unchanged. A private context index supplies native timezone/default mode; current native week rollover selects a new key. No per-card query, background polling, global account scan or sweep is added.

Known timetable stream heads and native permission facts bind the context. `dashboard-context.mjs` creates derived heads atomically with accepted ordered access/scope deliveries in existing `stream_heads`; no schema or backfill. Unchanged refresh clocks never advance these heads. Real role, enrolment, class/window, readiness and generation changes do. Scope Course policy has a separate native head used while Academy-owned; Studio FREE/PAID and acquired rights use local access/policy revisions and redecoration with zero Source requests. Ordinary/sensitive verification rules, original rights, exact delivery/retry guards and source tombstones remain unchanged. Stale-generation no-op deliveries do not replace semantic heads.

Native Academic permissions are not inferred from Studio facts or unchanged programme keys. Authoritative account/navigation updates always invalidate them. Same-epoch Teacher loss with retained Student membership is tested through real Source status delivery: cached Teach is denied; a valid current Student context can Learn. Known master-account fences block before private cache reuse. Actor, proof, current native/local heads and policy are rechecked after awaits and after writes.

Warm `serverTime,today,selectedDate` use the current server clock. `checkedAt` retains the native assembly/verification age, including policy-only redecoration; the twelve-hour age is never extended by a new decoration timestamp. Empty weeks are valid bounded negative snapshots. Known received changes invalidate on the next active request; unreceived changes still depend on normal bridge delivery, explicit refresh and verification expiry. This feature does not claim push notification of an undelivered change.

Bounds:32 enabled scoped offerings,200 timetable rows,50 decorated Course websites,230KB private snapshot,4KB metadata index and exactly seven displayed dates. Metadata invalidation uses indexed scope/account/stream lookups. `weekToken` describes a view revision; it is not an authentication or Join token. The separate frontend must invalidate its own remembered views on known account/permission/publication changes and consume this contract.
