# Yaseen: recorded lessons with companion reading

Local work on `feature/preview-course-cards`, 29 October 2026. No deployment, source Academy changes, hosted database queries, R2 uploads or live publication.

## Reading experience

The website introduction is compact, followed immediately by the “WATCH · LISTEN · FOLLOW ALONG” overview, without an instructional paragraph. Each authorised video has a prominent “Watch the full video” button, a short transcript-based overview when available, and a link to the associated companion reading. Recordings remain the lessons; the sixteen existing Yaseen readings remain supporting material. No watched/completed state is inferred from opening a video or reading a page.

The player sits in a separate sticky column on desktop and remains visible above the reading on mobile. It stays outside the redrawn reading DOM, so changing readings does not recreate the iframe. Closing it, leaving the website, or signing out removes playback; a late media response cannot reopen it after leaving. Normal full-screen video controls remain available. Viewing APIs, paid-month/whole-Course rights and website-only restrictions are unchanged.

Only permission-filtered media rows generate recording buttons. A button resolves its existing attachment through `/api/media/:id` before an iframe is created. Content cannot supply a YouTube URL or turn a website-only grant into recording access. No copied videos or PDFs are created.

## Editable summaries

Summaries use the existing editable source-note-aside component, in a short new section at the beginning of the relevant companion reading. `sourceKey: recording:<stable original lesson ID>` identifies the source recording; its title is the note attribution and its text is the overview. The homepage derives its summary cards from those notes and joins them to authorised media using the stable original lesson ID. This adds no content fields or new Save/Publish service. Both existing editors can edit the same note text using the shared validator and normal private draft/publication flow.

The new summary sections are separate from the author’s PDF text. A local package-preparation tool verifies that every original Yaseen reading/section and its text remain byte-for-byte identical. Added note/section IDs are deterministic so repeat preparation updates the same source summary while preserving other blocks. A paired ordinary quote block can supply an attributed transcript quotation, shown in italics with a rounded pink outline and no shading. It remains distinct from Quranic ayah/translation boxes. Private teaching packages and recording inventory stay outside Git and public assets.

## Topic and quotation navigation

The top of the recording overview offers “Read & reflect”, opening all sixteen companion readings and their reflection boxes. Each card’s “Read alongside this lesson” opens its matched reading. The current reader still has browser-held reflection notes only; a personal journal is not connected or implied.

Each of the five recorded lessons has a collapsible “Follow the recording by topic” guide, with 36 timestamps checked against the saved transcripts. Topic entries use an ordinary editable list with `sourceKey: recording-topics:<stable lesson ID>` and `m:ss / h:mm:ss Topic` items. The quotation timestamp uses the existing quote caption field. The full builder and on-page text editor retain the existing content format, validation and Save/Publish flow. No raw playback URL is stored in a content block.

Topic and quotation buttons resolve only an already-authorised video attachment. The initial open uses the existing media gate; seeking in the currently playing recording reuses that player’s source without a database query per topic. Starts are bounded non-negative whole seconds; invalid chapter entries are omitted. Topics are not attached to PDFs. The normal reading replaces its managed topic list with one interactive guide, without duplicating the list; editing retains the ordinary list and attribution fields. Playback is not counted as watched progress by this feature.

## Source review

The convenience transcript-export tool returned “No transcript is available”. That result was misleading: the human supplied a screenshot showing the visible Transcript panel. The five full transcripts were then retrieved from YouTube’s visible interface, with timestamps, and saved privately in the parent project output directory. Five summaries were prepared from these transcripts, with British spelling and the source’s practical teaching in view. Automatic-caption spelling is not copied blindly into the summaries.

All five overviews now address the reader directly in active, invitational language. Avoid reported speech such as “the teacher encourages” or “students are encouraged”. Use concrete everyday examples only when supported by the recording: the third summary draws on coffee and creamer, spices in a meal, complementary qualities in marriage, and day/night. Do not invent examples from a suggested illustration. These are editorial overviews, separate from the unchanged PDF wording. Five short quotations are checked against transcript segments. Their source attribution remains in the editable content; the learner-facing reference line is replaced with “Hear this in the recording”, which starts the original recording at that quotation. Scholarly quotations and Quranic references are unchanged. A paraphrase must never be presented as a verbatim quotation.

The local output `outputs/yaseen-recording-companion-20261029` contains the private transcript sources, reviewed recording guides, revised `private/yaseen-active-voice-package.json`, preservation audit and screenshots. `tools/prepare-recording-companion.mjs` prepares a separate package without changing its source. `tools/serve-recording-review.mjs` loads the existing saved preview copies and five recording references into a disposable local runtime, saves/publishes only that local Yaseen edition through the normal server service, and issues a synthetic local preview login. It never contacts hosted Academy or Cloudflare. Later copy changes merge into the current local editor document and save with its revision before local publication; they do not restart the runtime or replace unrelated edits. The user's in-app tab was refreshed and visibly verified with the current summaries, timestamped topic guides and quotation links.
